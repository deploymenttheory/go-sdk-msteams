# POL-08 contract inventory — MicrosoftTeams 8.1.0

Reviewed 2026-11-26 against main revision `bb56e7b`: **27 commands / 46 parameter sets / six families** from [issue #39](https://github.com/deploymenttheory/go-sdk-msteams/issues/39). All six native implementations exist at that revision. This source report does not close the research or child qualification tickets. No tenant scenario, permission change, token probe or Go build was run for this audit.

## Evidence and confidence

The [primary-source audit](pol08-primary-source-audit.md) independently resolves 15 compiled cmdlets and 12 functions, traces their selected processors, verifies seven package-file hashes and gives portable IL reproduction. The package identity is fixed by [8.1.0 provenance](../../../contracts/powershell/8.1.0/provenance.json). Exact names/types/binder validations/aliases/set defaults remain in [runtime metadata](../../../contracts/powershell/8.1.0/runtime.json); declarations alone do not prove server validation.

- **High confidence, local source:** resolved public exports, compiled property mapping/provider normalization, selected modern call chains, typed DTO/null/bound behavior and local constructor defaults. Each is tied to pinned source/hash/IL or controlled local serialization.
- **Scoped existing observations:** family records and fixture bytes below describe their recorded branch, tenant, authentication and parameter vectors. They are not new executions or a recertification of all variants.
- **Unknown/unqualified:** remote legacy server behavior, minimum per-operation RBAC, unobserved server value/default/effect semantics and remaining delegated/cloud/assignment scenarios. None becomes an exclusion or a guessed route.

Public exports, PowerShell flight selection, SDK backend and live evidence stay separate. A candidate mapping or unused compiled model is not the selected command contract. The ledger identifiers `teamsai_policy`, `teamsbyod_and_desks_policy`, `teamsip_phone_policy` differ from their Go directories; links are derived from actual symbol references, not generated from those resource spellings. No preview or qualification flags change.

## Native routes, identity and outcomes

Every route is under the selected Teams Admin origin with the Teams audience. No Graph lookup, arbitrary caller destination or cross-tenant selector is introduced. Exact types are TeamsWorkLoadPolicy, TeamsWorkLocationDetectionPolicy, TeamsAIPolicy, TeamsBYODAndDesksPolicy, TeamsIPPhonePolicy and TenantMigrationConfiguration; provider normalization was independently checked for the three compiled models.

| Operation | Compiled AI/BYOD/WorkLocation | Selected modern WorkLoad/IPPhone/TenantMigration |
|---|---|---|
| Get/list/filter | GET `/Skype.Policy/configurations/{type}[/configuration/{identity}]`; bare collection, exact Global first, local Identity/Tag wildcards | Same route family; case-insensitive Global-first partition and modern blank-selection defaults |
| Create | POST collection, bound-field serialization | POST/201 for WorkLoad/IPPhone; explicit POST/Get convenience retains separate creation/read-back receipts |
| Update | Sparse PATCH selected identity; Set preparation GET preserves read and patch acceptance separately | Sparse PUT/204; absent-Identity Global choice explicit; no compiled preparation GET |
| Delete | DELETE selected identity with compiled selector/optional string Force body | Bodyless DELETE/204 for WorkLoad/IPPhone |
| Grant | User/tenant PATCH, group POST on `/Skype.Policy/users/{user}/policies/{type}`, `/tenants/policies/{type}`, `/groupPolicyAssignments/{group}/policyTypes/{type}` | Same route shapes for WorkLoad/IPPhone, different modern body/control/rank rules |

Compiled identities split at the first slash and escape the remaining name as one component; modern names are escaped whole. Compiled requests use MPACmdlet, command metadata and correlation UUID without generated discovery. Modern requests use same-session discovery/validated forest targeting without MPACmdlet. The selected helpers pass null ApiVersion/SchemaVersion, so no version queries are injected. Mutations never replay or implicitly roll back; no invented collection paging or assignment polling is added.

TenantMigration has only public Get/Set: it does not gain create/delete/grant from the other table columns. It controls MMS through MeetingMigrationEnabled. It is distinct from [TeamsMigrationConfiguration](../../../msteams/teams_admin_api/teams_migration_configuration/api_docs.md) client interop and from CORE private-channel migration status on a separate backend/audience. A failure or success on one does not establish another migration resource. Returned XML Authority metadata is also distinct from OAuth authority or role assignment.

For compiled Create, omission is not blanket null filtering. BoundParametersContractResolver selects properties by bound key; controlled local serialization distinguishes absent, explicit null and false. Fresh WorkLocation models have both settings null and their constructors inject neither False nor Disabled. Published creation/default semantics therefore do not authorize the SDK to substitute those values when the caller leaves fields unbound. The source audit records constructors, binding checks, serializer/resolver method offsets and local vectors.

Read models retain nullable typed values, future fields and complete owned raw snapshots. Mutation DTOs send evidenced bound settings rather than replaying received unknown fields. A bound malformed response can retain acceptance plus a decode error; source/HTTP acknowledgement is not persistence or effective policy. Raw XML Key/Authority metadata is retained per response; existing cross-read observations do not make every internal field an immutable state value. No settings values or tenant identifiers are copied into this report.

## Assignment scope and controls

Compiled AI/BYOD/WorkLocation Grant exposes explicit user/group/tenant scopes plus a parameterless Identity set with no source operation. Missing/mixed scope fails locally. Required signed Int32 group rank is always sent, including zero/negative; nil/empty PolicyName remains distinct. User/group DTOs use policyName, tenant uses PolicyName with additionalParameters:null and Boolean forceSwitchPresent. CRUD Force is string-encoded; tenant Force is a separate Boolean.

Modern WorkLoad/IPPhone Grant requires a bound PolicyName despite optional public metadata. Its helper omits zero Rank, whereas the lower native group primitive can send explicit zero. No public Force setting is invented from the lower tenant helper. Public PassThru output control does not turn a 202 receipt into effective assignment; native methods return explicit responses. Successful CRUD is not live assignment/clear/convergence proof.

## Current documentation versus the pinned baseline

Checked 2026-11-26. Current help is useful product context, but does not rename or add fields to a verified 8.1.0 declaration.

- [New AI policy](https://learn.microsoft.com/en-us/powershell/module/microsoftteams/new-csteamsaipolicy?view=teams-ps) uses SpeakerAttributionBYOD and omits PassiveVoiceEnrollment in its displayed syntax. The pinned runtime and compiled New/Set mappings instead bind SpeakerAttributionForBYOD and PassiveVoiceEnrollment; no corresponding aliases exist. The help's malformed value/parameter-set table does not become extra metadata sets or a new local enum.
- [New work-location policy](https://learn.microsoft.com/en-us/powershell/module/microsoftteams/new-csteamsworklocationdetectionpolicy?view=teams-ps) describes default outcomes and Ask/Inform consent behavior. Those descriptions are not local constructor defaults or proof of device/Wi-Fi behavior. The pinned nullable Boolean/String settings remain omitted when unbound; server outcomes need their own observation.
- [Set tenant migration](https://learn.microsoft.com/en-us/powershell/module/microsoftteams/set-cstenantmigrationconfiguration?view=teams-ps) displays Instance/Tenant/Force controls absent from the actual public 8.1.0 runtime. They are not added as native wire settings. The only assigned setter setting is MeetingMigrationEnabled, and the tenant stays bound to the session.
