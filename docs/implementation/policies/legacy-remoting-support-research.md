# Teams legacy remoting support research

Reviewed **2026-11-26** against MicrosoftTeams **8.1.0**. This is a read-only, primary-source lifecycle investigation supporting the POL backlog. It does not change SDK scope, exclusions, qualification, authentication, or tenant state. No tenant commands, protocol probes, builds, or package downloads were performed. The retained module `/private/tmp/msteams-core90-pinned/module` was not changed.

## Finding

**The reviewed primary evidence does not establish that the pinned legacy TRPS branch is retired, internal-only, or unreachable. It also does not establish universal modern API availability independent of tenant/session flight selection.** Modernization is documented and the pinned package supplies native HTTP candidate contracts, so modern SDK implementation remains actionable. Those facts do not settle the remote branch or prove complete management parity for every tenant/cloud/authentication/parameter combination. This is the interpretation of the bounded evidence below, not a Microsoft support declaration.

## Pinned source boundary

The detailed source findings remain in the [POL-04 audit](https://github.com/deploymenttheory/go-sdk-msteams/blob/de4218ca88f001a65117a206176886b52541e307/docs/implementation/policies/pol04-primary-source-audit.md) and [POL-05 audit](https://github.com/deploymenttheory/go-sdk-msteams/blob/b10b5e72b6e5c3bf4ed2bb071a75eb8867d7d3a5/docs/implementation/policies/pol05-primary-source-audit.md), especially their conditional dispatch sections. These revision-bound reports cite the actual package methods and IL offsets; they are analysis of the first-party package, not first-party server specifications. The externally obtainable package is [MicrosoftTeams 8.1.0](https://www.powershellgallery.com/packages/MicrosoftTeams/8.1.0).

For reproducibility, the source owners/locations recorded there are:

- `bin/Microsoft.Teams.ConfigAPI.Cmdlets.private.dll`, `Microsoft.Teams.ConfigApi.Cmdlets.TrpsPSCmdlet.BeginProcessing`: hidden mode handling, accepted `Legacy`/`TryModern`/`ForceModern`, removal before forwarding. `TryGetFlightedApi` and `FlightingUtils.GetFlightingCommandInfo` consult session modern-remoting flight information and candidate availability.
- The same binary, `TrpsPSCmdlet.getProcessor` and `CreateTrpsPipelineProcessor`: modern processor versus actual remote runspace processor. `RemoteSyncProcessor.ReceiveOutput` adds the public command, attaches the runspace, and invokes PowerShell.
- The same binary, `TrpsSessionBuilder.CreatePSSessionAndUpdateSessionStore` and `PSCommands`' explicit `IPSCommands.NewPSSession`: HTTPS `/OcsPowershellOAuth/` plus `?AdminDomain=`, New-PSSession with Basic selection and an OAuth credential. The Basic transport selection is not evidence of ordinary password-authentication support.
- `custom/CmdletConfig.json` and `custom/Merged_custom_PsExt.ps1`: modern helper mappings and their local behavior. Generated ConfigAPI methods supply the direct HTTP request candidate contracts separately from selection of those candidates.

The reviewed existing audits establish these local branches, not their live reachability. Their conditional execution evidence prevents treating modern mapping presence alone as proof that the default public command always chooses modern HTTP. Conversely, retained branch code does not prove continued server support. The Connect documentation's no-Basic-enable requirement and the retained Basic-selection code are different evidence layers; neither licenses inventing the missing global flight state. [Sources: pinned package locations above; POL-04/POL-05 conditional-dispatch sections; Connect reference above.]

## Consequence for the active backlog

No exclusion, source-settlement promotion, or tenant-qualification promotion follows from this investigation. Retain the existing split:

1. **Local modern contracts:** implement and verify the pinned source-derived modern request/binding behavior in native Go where that behavior is established. No runtime PowerShell dependency is required for those known HTTP operations. This is an engineering implication of the pinned helper/generated request contracts, not a claim of universal service availability.
2. **Remote behavior:** retain unknown/unqualified status for server binding, validation, results, authorization and effects behind the conditional remote handoff. A direct implementation of modern HTTP does not by itself demonstrate equivalence to that server branch.
3. **Decisive missing evidence:** a Microsoft statement explicitly retiring the Teams endpoint/branch or guaranteeing all relevant modern APIs without legacy-flight dependence; first-party server contracts/source establishing equivalent semantics; or separately authorized pinned execution/comparison evidence for the particular scenarios at issue. No such evidence was obtained in this read-only research.

Searches covered the official Teams release notes, pinned Gallery notes/manifest, supported-version policy, connection reference, application-authentication documentation, security guide and relevant cmdlet references. Searches also looked for first-party statements using TRPS, remoting, modernization, retirement and OcsPowershellOAuth. Search non-results are only a record of investigation coverage. They are not proof of retirement or continued support. Exchange Online RPS retirement, community posts, modern-only lab success and host-specific remoting limitations are not used as Teams TRPS lifecycle evidence.
