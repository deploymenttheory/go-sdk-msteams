# POL-01 federation, branding, voicemail and application meeting contracts

Research revision: **2026-11-20**, pinned MicrosoftTeams **8.1.0**. This note
covers the remaining **29 commands** in [POL-01](../backlog/issues/POL-01.md):
application meeting configuration (2), federation (14), meeting branding (8)
and online voicemail policy (5). The other eleven commands have separate
[application access](application-access-contract-evidence.md) and
[assignment migration](assignment-migration-evidence.md) notes. This is static
client evidence, supplemented by current first-party documentation. No
credentials, connection, live tenant request or cmdlet `ProcessRecord` execution
was used. Source-derived JSON examples below are synthetic, not service captures.

The primary Go surface is resource CRUD/list plus explicit assignment actions.
Three policy resources have evidenced Create/Get/List/Update/Delete contracts;
the four configuration resources have Get/List/Update evidence only. The six
domain/image/theme constructors build local values for those resources. Generic
provider methods and a `New-` verb do not establish an additional service route.
All 29 commands remain in parity scope; the unresolved questions at the end
prevent a claim that every backend contract or live behavior is complete.

## Routing, token and header boundary

R `BaseTpmGet/New/Set/Remove/GrantCmdlet.ProcessRecord` asks
`CmdletHostExtensions.GetConfigApiTokenEnvironmentForDeterminingScope` for an
environment, then `CmdletHostWrapper.GetAccessToken` for that ConfigAPI app ID
and its `/user_impersonation` scope. Outside SelfHost the first helper returns
Public; the public resource is **`48ac35b8-9aa8-4d74-927d-1f4a14a0b239`**.
`CmdletHostWrapper` packages that resource/scope plus host context into H
`TokenGenerationInfo`; K
`Microsoft.TeamsCmdlets.PowerShell.Connect.TPMCmdletHostContract.GetAccessToken`
uses the active session, resolves selected/custom cloud endpoints and returns
`LoginInfo`. This does not imply a delegated-only service restriction: shared
host application-mode token acquisition and `/.default` handling are documented
in [session evidence](../auth/session-evidence.md). [R methods above; H
`DeploymentConfiguration`; K method above.]

The R request helper uses **`https://{loginInfo.ConfigApiEndpoint.Host}`** as
origin, then `/Skype.Policy/...`. It does not preserve an endpoint's path or
custom port. H `DeploymentConfiguration.ConfigApiEnvironmentToEndpoints` maps
Public to `https://api.interfaces.records.teams.microsoft.com`, GCCH to
`https://api.interfaces.records.gov.teams.microsoft.us`, DoD to
`https://api.interfaces.records.dod.teams.microsoft.us` and China to
`https://api.interfaces.records.teams.microsoftonline.cn`; further internal
cloud mappings remain in shared routing evidence. A cloud tuple is not proof
that every policy feature is deployed there. These requests are ConfigAPI
policy administration, not Microsoft Graph. [R `HttpRequestHelper<TPolicy>`;
H deployment configuration; K host token method.]

R `HttpRequestHelper.AddAdditionalHeaders` adds `X-MS-CmdletName`, a per-request
`X-MS-Correlation-Id` and the policy-administration/module User-Agent.
`HttpClientHelper.CreateHttpClient` adds `MPACmdlet: true`;
`SendRequestAsync` adds the bearer. JSON bodies are UTF-8
`application/json`. Internal SelfHost/Torus may additionally inject roles,
forest, tenant or arbitrary OCE context headers; an ordinary request to these
paths gets no unconditional tenant-ID header. **This provider does not call
the generated forest-discovery callback or add `X-MS-Target-Uri`.** Do not copy
that generated bootstrap onto the R routes. [R named methods,
`HttpRequestHelper.AddOrUpdateOCERelatedHeaders`.]

By contrast, the selected P generated calls for application meeting settings,
tenant federation settings and voicemail Grant use `Generated.Module` and
`Custom.SendAsyncCallback`. Their ordinary path includes ConfigAPI
`GET /Teams.Tenant/serviceDiscovery`, reads `Endpoints.AdminServiceEndpoint`,
and adds its root as `X-MS-Target-Uri` while still sending to the selected
ConfigAPI origin. The shared resource/authority, discovery failure and cloud
rules are traced in [policy routing evidence](../core/policy-routing-evidence.md)
and verified here against P `Generated.Cmdlets.GetCsConfiguration_Get/Get1`,
`SetCsConfiguration_Update`, `GrantCsUserPolicy_GrantExpanded`,
`GrantCsTenantPolicy_GrantExpanded` and
`GrantCsGroupPolicyAssignment_GrantExpanded.ProcessRecordAsync`. A successful
login or flight response alone establishes neither backend authorization nor
operation deployment.

Let `T` be the exact A model name: `ExternalAccessPolicy`,
`TeamsAcsFederationConfiguration`, `TeamsExternalAccessConfiguration`,
`TeamsMeetingBrandingPolicy` or `OnlineVoicemailPolicy`. R
`Helpers.ConfigurationNameNormalization<TPolicy>.GetNormalizedNameForPolicyRP`

as a path separator and escapes the prefix and remainder separately; otherwise

in any compatibility fixture. Colon-prefixed names are not client-normalized to
another spelling. [R `HttpRequestHelper<TPolicy>` and name-normalization helper.]

R method citations for the verbs are `HttpRequestHelper<TPolicy>.GetAsync`,
`GetAllAsync`, `CreateAsync`, `SetAsync` and `RemoveAsync`. All requests in this
subset have **no apiVersion/schemaVersion/query parameters**. R
`CmdletExecutionData.SetQueryParameters` only considers a named `QueryParameter`
set, which none of these A commands has; it is not a paging mechanism. Set's
first GET passes its query string while its later PATCH omits it; the difference
has no effect for these commands. [M; R bases and execution-data methods.]

The PowerShell compositions matter:

* **Get:** omitted Identity makes one collection request. It decodes a bare
  `List<TPolicy>`, applies optional local PowerShell `-like` filtering to Identity
  or `Tag:{Filter}`, and outputs exact `Global` identities before other results.
  Supplying Identity makes one item request. No OData filter or continuation
  query is emitted. Identity/Filter have `ValidateNotNullOrEmpty` in compiled
  metadata; Filter and Identity are separate parameter sets. [R
  `BaseTpmGetCmdlet.ProcessRecord/FilterPolicies`; M.]
* **New:** mandatory Identity and optional Force accompany the family fields.
  It constructs a new model. For a non-Global name it first tries GET `Global`
  for confirmation comparison; failure is a warning and does not prevent the
  POST. The reference Global object is **not cloned into the new model**.
  After `ShouldProcess`, it applies bound values, POSTs the sparse body and
  returns a decoded object only if the POST has content. There is no automatic
  post-create GET. [R `BaseTpmNewCmdlet.ProcessRecord`; A `CreateNew/UpdateProperties`.]
* **Set:** mandatory nonempty Identity; optional Force; at least one
  family-specific property must be bound, even if its value is false/null/empty.
  Otherwise it reports a local no-parameters error before acquiring a token.
  It GETs the current object, performs `ShouldProcess`, applies the bound
  properties and PATCHes. The transport body is sparse despite the read: the
  serializer selects bound property names. Identity in the body comes from the
  read model; the route still uses the supplied Identity. [R
  `BaseTpmSetCmdlet.ProcessRecord`; A `AreParametersSpecified/UpdateProperties`;
  R bound-parameter resolver.]
* **Remove:** mandatory nonempty Identity (pipeline by property name accepted)
  and optional Force. It performs `ShouldProcess` before token acquisition and
  DELETEs with an **application/json body** containing the bound `Identity`;
  it does not GET first. Bound Force adds its string-valued control. [R
  `BaseTpmRemoveCmdlet.ProcessRecord`; `HttpRequestHelper.RemoveAsync`.]

New and Set can make their comparison/current-object GET before a `WhatIf`
decision; Grant and Remove decide `ShouldProcess` before token acquisition.
Consequently dry-run is not equivalent to a network-free operation. This is
the inspected control-flow contract, not a live invocation claim. [R bases.]

### Provider request presence and response/error handling

R `Helpers.BoundParametersContractResolver.CreateProperty` writes a model
property only when the bound-parameter dictionary contains its exact JSON
property name. Models here have **PascalCase** CLR/JSON property names and no
family naming strategy. Unbound nullable Booleans, strings, collections and enum
fields are omitted; a bound false survives; bound nullable null is included as
JSON null where the model setter and PowerShell binding permit it. Preserve
presence separately from zero values in Go. No model constructor assigns
service-level Boolean defaults. Read defaults, absent properties and explicit
JSON null must not be conflated. [R resolver and `CreateAsync/SetAsync`; A models.]

`HttpRequestHelper.GetNestedBoundParameters` adds every public property name
of a bound list's element type, recursively for nested lists. Therefore a bound
branding list writes its elements' scalar properties, including default nulls
and initialized empty nested collections; it does not send the list modifier's
`Add`/`Remove` object. JSON arrays are flat under the public property names, even
where a private model backing field uses a wrapper class. R
`AddAdditionalBodyContent` then adds any bound non-common parameter missing from
the serialized object by `.ToString()`. In particular bound **Force becomes
`"Force":"True"` or `"Force":"False"`**, not a Boolean. Default unbound Force
is absent. This helper assumes the added value is non-null and can fail before
send if a null value reaches this path; it is not a general null-normalizer.
Common and optional PowerShell parameters are excluded via
`CommonParameterNames.ToExcludeInRequestsToPolicyRP`. [R named methods.]

R `HttpClientHelper.SendAsync<TPolicy>` accepts **any 2xx** through
`IsSuccessStatusCode`; if content is nonempty it deserializes one `TPolicy`, and
empty success content produces no object. `GetAllAsync` expects a bare JSON
array, not `{value:...}`. The client does not declare separate 200/201/202/204
schemas or a family-specific status table. A 202 body containing an operation
ID would still go through the `TPolicy` decoder; these provider Grant paths do
not expose the generated client's typed operation handle. Keep status, raw
body and headers available in native results, and do not equate every 2xx with
completed policy propagation. [R methods above; `PolicyResponse`.]

All non-2xx statuses become `PolicyRpException(rawBody)`, losing HTTP status in
that exception. R `ExceptionHelper.CreateErrorRecord` tries to deserialize
`ErrorModel` with `Code`, `Message`, `Action`, `ErrorCode` (Newtonsoft default
case-insensitive matching), and concatenates Message/Action for PowerShell.
This does not prove a server-required spelling or any specific 400/401/403/404/
409/429 error code. Non-JSON/malformed errors can fail the presentation decoder.
Native errors must retain HTTP status, request/correlation headers and raw bytes
when structured decoding fails. Missing resources, authorization failures,
rate limiting and malformed bodies must remain distinct. Successful responses
may supply `X-Ms-ConfigApi-PowerShell-WarningMessage`, which the bases display.
[R `HttpClientHelper`, `ErrorModel`, `ExceptionHelper`, `BaseTpmCmdlet.DisplayWarnings`.]

The inspected helper sends each request once. It contains no retry/Retry-After
loop, continuation parser, async polling, transfer/upload code, ETag/If-Match,
idempotency key or mutation replay rule. `GetAllAsync` makes one request; this
does not establish absence of hidden server truncation. The PowerShell
Task.Run/Result mechanism does not implement native caller cancellation; Go
must carry context through its own transport boundary. Do not replay ambiguous
POST/PATCH/DELETE submissions or assume the preceding GET makes list changes
atomic. [R HTTP helpers and base cmdlets.]

For each string list, `UpdateProperties` clears the model list when its bound
modifier is null or `IsEmpty()`, otherwise `ApplyTo` changes it. With Set this
uses the fetched current list; with New it uses an empty initialized list.
The PATCH/POST carries the resulting entire array. Scalar fields are assigned
only when bound. The source initializes domain regex fields but does not call
them from these list setters; Description's length reads do not enforce a
1–1040 bound. Do not invent those client validation checks from dead constants.
Service-side domain/name/range validation remains unobserved. [A command
`UpdateProperties` methods and `ExternalAccessPolicy` setters/constructor.]

Current [New external-access documentation](https://learn.microsoft.com/en-us/powershell/module/microsoftteams/new-csexternalaccesspolicy?view=teams-ps)

prerequisites, not additional management endpoints. Its Tenant/InMemory
parameters are absent from M for this pinned compiled command and must not be
added as observed 8.1.0 parameters.

## External-access and branding assignment actions

These two A Grant classes directly inherit R
`BaseTpmGrantCmdlet<TPolicy>`. Their common scope contracts differ from the P
voicemail Grant below. All body examples here are source-derived:

| Action | Parameters | Relative method/route and JSON body |
| --- | --- | --- |
| AssignUser | Mandatory nonempty string `Identity`, optional nullable/empty `PolicyName` | PATCH `/Skype.Policy/users/{escapedIdentity}/policies/{T}`; `{"policyName":"Fixture","additionalParameters":null}` |
| AssignTenantDefault | Mandatory `Global` switch, optional `PolicyName`, optional `Force` (default false) | PATCH `/Skype.Policy/tenants/policies/{T}`; `{"PolicyName":"Fixture","additionalParameters":null,"forceSwitchPresent":false}` |

names `additionalParameters`/`forceSwitchPresent`. Its Force Boolean is always
populated from the switch, even when false, unlike the string-valued CRUD Force
control. R `AdditionalParameters` is unpopulated by these Grant bases and is
serialized null. [R `HttpRequestHelper.GrantToUserAsync/GrantToTenantAsync/GrantToGroupAsync`,
payload models; `BaseTpmGrantCmdlet.ExecuteGrant`; M.]

PolicyName is **not checked for presence** by this base; its local
`AreParametersSpecified` always returns true. Missing/null PolicyName reaches
the DTO as JSON null; an explicit empty string remains empty. This proves the
emitted request, not that each scope treats null/empty/missing as a successful
clear. Native assignment and clear actions must preserve those distinctions
until qualified. There is no Rank range validation, group identifier resolution
or preflight GET in this implementation. A Group string is sent directly, not
resolved through Graph. [R base and DTOs.]

M contains a fourth, default **`Identity` parameter set with only common
parameters** for both compiled Grants. The R switch only handles `GrantToUser`,
`GrantToGroup`, `GrantToTenant`; its default reports inability to determine a
grant and returns `PolicyResult=false`, without a grant HTTP request. This is
an evidenced client disposition, not a fourth assignment scope. A correct SDK
requires an explicit scope and does not expose a no-argument assignment method.
[A Grant Cmdlet attributes; M; R `BaseTpmGrantCmdlet.ExecuteGrant`.]

The R response/error rules above apply to all three scopes: any 2xx, optional
TPolicy decoding, no typed group-operation ID or polling. Do not borrow the P
generated 202 response contract merely because the route text matches. User
pipeline input is processed record by record through this base; no batch
transaction or rollback is evidenced. [R Grant `ProcessRecord` and HTTP helpers.]

## Authorization, restrictions and remaining questions

Current [application authentication guidance](https://learn.microsoft.com/en-us/microsoftteams/teams-powershell-application-authentication)
(revision **2025-09-17**, checked **2026-11-20**) generally supports these
commands in commercial/GCC and GCCH/DoD; none of the 29 appears in its explicit
exception list. It requires appropriate directory-role RBAC on the application
and documents Graph Organization.Read.All for module setup, plus additional
Graph permission when administrative units are used. Those Graph permissions
are not the audience of a policy-management request, and no extra Teams Tenant
Admin API permission should be inferred. It does not establish the minimum
role, administrative-unit behavior or sovereign-cloud feature availability for
each operation. The ACS-specific role statement, branding licensing and
voicemail-preview restriction above remain distinct qualifications.

Static source settles the selected client request contracts. The following
unresolved wire/dispatch items block affected implementations or parity claims;
they must not be filled with guessed endpoints or successful-empty results:

| Question | Established boundary / required resolution |
| --- | --- |
| Do application meeting/tenant federation configurations support Create/Delete? | Only Get/List/Update command chains are evidenced. Keep native Create/Delete unavailable/unevidenced until an authoritative contract establishes support. |
| Do unselected remoting commands accept the modern contract in every eligible tenant? | Command-specific flight selection is proved; service-wide acceptance is not. Also settle outer wrapper PassThru/WhatIf binding and explicit-null coercion with isolated binding evidence before claiming equivalence. |
| What exact tenant-federation response shape represents allow-all, empty allow-list, explicit list and null? | Set's emitted sentinel/array/operator requests and Get's presentation fixup are known; no service response capture/discriminator schema is available. Retain raw JSON and add separate decode variants. |
| What are legal identities and canonical spelling/scopes? | Provider first-slash escaping and generated full-segment escaping are proved. Tag:/scope normalization, Global mutation/removal rules and unsupported identity rejection are not observed. Global-only current documentation is not proof of every compiled binding choice. |
| How does each scope clear an assignment and handle missing/empty PolicyName? | R sends JSON null or empty, P adapter requires presence and can coerce null to empty; service clear/tenant-default/group behavior is unobserved. Do not alias all three forms. |
| Which statuses/payloads do compiled group assignments actually return? | R accepts any 2xx and decodes TPolicy; it neither declares a job ID schema nor polls. P voicemail Grant separately declares 202 OperationId/204 and supports a distinct job-read method. |
| How do invalid element values, null object-list modifiers and model constraints fail? | Local source validation and list comparison/removal behavior are above; complete PowerShell binding, backend range/domain/language validation and field defaulting require explicit fixtures/qualification. |
| Are sparse provider updates/list replacement atomic, and are deletes of assigned policies accepted? | No ETag/precondition, concurrency or deletion-policy semantics are established. R list operators read/modify/write; do not claim atomic Add/Remove or safe automatic retry. |

The following are **unobserved live qualification**, not missing client-route
evidence: successful service responses; duplicate/missing policy and malformed
input errors; 401 versus 403/RBAC/administrative-unit failures; rank bounds and
group identifier acceptance; cloud/tenant rollout and licenses; hidden list
limits/truncation; propagation/consistency and operation completion; service
retry/Retry-After/idempotency behavior. No lab calls were attempted.

Downstream contract fixtures should cover the seven resource types separately:
object versus bare-array reads; generated PUT versus provider PATCH; escaped

read/modify/write versus generated Add/Remove operators; numeric external enum;
voicemail TimeSpan strings; nested branding nulls/arrays; bound Force's differing

the compiled no-scope parameter-set error; generated 202/204 with no automatic

Mark source-derived fixtures, isolated in-memory observations and live captures
separately. This note does not itself create endpoint manifests/fixtures, mark
