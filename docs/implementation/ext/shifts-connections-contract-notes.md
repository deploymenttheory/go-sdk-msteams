# Shifts connection contracts

Owner: #90 (EXT-27). Baseline: MicrosoftTeams 8.1.0.

All twelve cmdlets are AutoRest cmdlets in
`Microsoft.Teams.ConfigAPI.Cmdlets.private.dll`. The generated
ConfigApiBasedCmdlets methods give the wire routes under
`/Teams.ShiftsConnector/api/v2`:

- Connectors: GET `/connectors`, envelope `value` of
  `{supportedSyncScenarios, id, name, version}`.
- Connections: GET `/connections`, GET/PUT/PATCH/DELETE `/connections/{connectionId}`,
  POST `/connections`. Get, New, Set and Update also send the cmdlet's optional
  `-Authorization` string as a raw `Authorization` header; the SDK
  authenticates with its own credential and does not expose it. Set (PUT) and
  Update (PATCH) send the optional `-IfMatch` as `If-Match`.
- Instances: GET `/connectorinstances`, GET/PUT/PATCH/DELETE
  `/connectorinstances/{connectorInstanceId}`, POST `/connectorinstances`.
  `-IfMatch` is mandatory on Set and Update.
- Test-CsTeamsShiftsConnectionValidate: POST `/Teams.ShiftsConnector/api/v1/connect`
  (v1, not v2), body `ConnectorInstanceBaseRequest`.

Model serializers give the property names:

- `WfmConnectionRequest`: `name`, `connectorId`, `connectorSpecificSettings`,
  `state` (all mandatory in NewExpanded). `UpdateWfmConnectionRequest` and
  `UpdateWfmConnectionFieldsRequest` add `_etag`; every field is optional.
- `ConnectorInstanceRequest`: `syncScenarios`, `connectionId`,
  `connectorAdminEmails`, `designatedActorId`, `name`, `syncFrequencyInMin`
  (int32), `state`. The update requests add `_etag`. The nine
  `-SyncScenario*` parameters map to `offerShiftRequest`, `openShift`,
  `openShiftRequest`, `shift`, `swapRequest`, `timeCard`, `timeOff`,
  `timeOffRequest`, `userShiftPreferences`.
- `WfmConnectionResponse`: `connectorSpecificSettings`, `id`, `tenantId`,
  `connectorId`, `name`, `etag`, `createdDateTime`, `lastModifiedDateTime`,
  `state`. `ConnectorInstanceResponse` adds `connectionId`,
  `connectorAdminEmails`, `designatedActorId`, `syncFrequencyInMin`,
  `syncScenarios` and `workforceIntegrationId`.
- Connector-specific request settings: Blue Yonder `adminApiUrl`,
  `siteManagerUrl`, `essApiUrl`, `retailWebApiUrl`, `cookieAuthUrl`,
  `federatedAuthUrl`; UKG Dimensions `apiUrl`, `appKey`, `clientId`,
  `clientSecret`, `ssoUrl`; base `loginUserName`, `loginPwd`, `_type`. Response
  settings carry the URLs, `appKey`, `clientId` and `ssoUrl` but no password or
  client secret. The SDK sends `Settings` as a free-form map so new connectors
  need no SDK change, and redacts every request type that carries it.

The module constrains no state or sync scenario values, so the SDK keeps them
as strings. `-PassThru` on the Remove cmdlets is PowerShell-only.

Lab observations (client-secret, app-only Teams Administrator):

- Every route, read or write, returns HTTP 403
  `{"code":"Forbidden","message":"Access Denied.","action":"Provide different credential or request access."}`.
  The denial comes before validation: creates with reserved connector IDs and
  `example.invalid` URLs, writes and deletes to reserved IDs, and the v1
  validation probe are all denied the same way, so nothing was created or
  changed.
- PowerShell writes the 403 body to the pipeline as
  `ErrorResponseAutoGenerated2` and records no error. The SDK returns a typed
  `*client.APIError` (`auth.ErrForbidden`).

Because the lab cannot create a connection, no owned `msteams-sdk-*`
connection exists and recovery needs no registration.

Acceptance: `TestAccShiftsConnectionsAuthorizationDenied` (read-only, with
pinned PowerShell output-type parity) and
`TestAccShiftsConnectionsRejectedWrites` (serial; every write targets
`00000000-0000-4000-8000-00000000000{1,3}` or `example.invalid`). Sanitized 403
responses from these runs feed the unit contract tests. Successful read and
write bodies, etag semantics, validation results and real WFM behaviour remain
unqualified and need credentials the Shifts connector accepts plus a WFM test
system.
